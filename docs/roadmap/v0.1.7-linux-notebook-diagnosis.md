## Observed blocking path

In the locked kernel, startup reaches `IPKernelApp.init_kernel`, after ZeroMQ sockets
and service threads have been created. Importing the debugger initializes debugpy
logging, which queries `platform.platform()` and the lazily cached
`platform.processor()`. The latter starts `uname -p` through Python's subprocess
implementation. A function-entry trace stops at `fork_exec`.

The failure can be reproduced without Phi, Jupyter, debugpy or pyzmq: a Python thread
blocks **SIGTRAP in its signal mask**, waits in `epoll`, and the main thread calls
`os.fork()`. The same-version ARM native control succeeds; the x64/Rosetta control
stalls. This is a signal-mask condition, not a signal-handler/disposition change.

Similar first-hand reproductions are documented in
[Apple's container issue tracker](https://github.com/apple/container/issues/966)
and a [Docker Desktop Jupyter report](https://github.com/docker/desktop-feedback/issues/592).
Those reports corroborate the local measurements; they do not substitute for them
or prove Rosetta's internal implementation. No claim is made about every OS or
Rosetta version, or about a future update fixing the issue.

## Reusable environment probe

Added [notebook-fork-probe.py](../../scripts/acceptance/notebook-fork-probe.py).
It uses only Linux Python standard-library facilities and creates no network/model
requests or configuration changes:

```sh
python3 scripts/acceptance/notebook-fork-probe.py trap-epoll
python3 scripts/acceptance/notebook-fork-probe.py none-epoll
python3 scripts/acceptance/notebook-fork-probe.py usr1-epoll
python3 scripts/acceptance/notebook-fork-probe.py trap-sleep
```

Use the intended Python interpreter (Python 3.9+). Exit 0 means this diagnostic case
completed; it is not a Notebook acceptance pass. Exit 124 means the owned case hung
and was cleaned up after five seconds. Unsupported/invalid inputs fail nonzero.
Each case runs in an owned process group, and SIGINT/SIGTERM cleanup reaps that
group. Thread errors/early termination fail instead of printing a false success.
The probe does not attempt to handle uncatchable termination of its supervisor.

Verification: both architectures repeated the eight-case matrix with the expected
seven completions/one timeout; the same x64 interpreter under QEMU completed the
trigger case. Real SIGINT/SIGTERM tests returned 130/143 with no children left;
a failed polling-thread injection was rejected. Python syntax checks passed.
Related Notebook regressions: **68 passed, 0 failed**. Type checks and lint passed
(0 errors / 1,376 existing warnings); no threshold changed. The full application
suite was not rerun for this diagnostic/docs-only change; its previous 8,069-pass
result is historical, not a fresh result for this round.
