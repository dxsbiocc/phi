## 安全且可重复的验收准备

参考 `deepseek-harness` 固定修订 `00102833dfaee1da9f48a3a8eae9d34005a75218`
的 `packages/ssh/ssh/tests/live.e2e.ts`：只有显式给出测试目标才启用真实测试；每次在被允许的可写目录下建立带随机 ID 的一次性子目录；只删除该子目录；失败也断开测试连接。Phi 使用自己的 OpenSSH 会话和项目/Wrapper 服务，不启动 DSH helper，也不借用上游“连接断开即清理托管进程”的生命周期。

1. 准备两个经管理员允许的目标：普通 POSIX SSH 主机，以及可以提交小型测试作业的 Slurm 集群。分别给出 OpenSSH 别名和**现有**可写测试父目录。两者可在同一集群上，但须分别覆盖 `detached_ssh` 与 `slurm-controller`。不要把个人数据目录当作可清理测试根。
2. 在本机现有 OpenSSH 配置中完成认证与 `known_hosts` 指纹核对。Phi 强制 `BatchMode=yes` 和 `StrictHostKeyChecking=yes`，不提供交互式口令/MFA。记录 `ssh -V`，以及远端 `nextflow -version`、`java -version`、容器运行时版本；Slurm 目标另记 `sbatch --version`。只记录版本和别名代号，不保存用户名、真实主机名、密钥、环境变量或绝对私有路径。
3. 由测试人员在每个测试父目录中建立 `phi-e01-<随机 ID>` 子目录。每个 UI 项目和 Wrapper 输出仅指向各自子目录。结束后确认作业已完成，再清理**该随机 ID 子目录**，保留其他远端文件。
4. 在 Phi 的远程设置中对已有 OpenSSH 别名执行“测试连接”，无需另行添加；新建项目时直接选择该主机和测试子目录，权限设为“重要操作前询问”。保留诊断每项状态、创建结果和项目侧栏连接状态截图或简短记录。

设置页把从 OpenSSH 配置识别的主机和既有 Phi 档案列成清单。OpenSSH 主机直接出现在新建远程项目的服务器选项中，不需再点击“添加”；顶部“添加服务器”会写入新的 `Host` 到 `~/.ssh/config`，清单行的“编辑”修改可安全定位的单别名配置段。保存前用 `ssh -G` 检查结果，再原子替换并在同目录留下仅当前用户可读的备份。对共享 `Host` 规则或 `Include` 文件中的别名，界面会返回明确的手动编辑提示，不覆盖其他主机配置。尚未配置远程运行的本地项目默认收起。密码认证尚未接通。
