## Product defect repaired

SSH password bootstrap could hang after successful authentication: `ssh -M -N -f`
exits its launching process while the master retains inherited pipes. The command
runner waited only for `close`; its timeout killed an already-exited parent without
settling the promise. An independent actual-Node reproduction with a 100 ms timeout
returned after about two seconds with **exit code 0 and a timeout message**.

The runner now settles deadlines as failure (`exitCode: null`) and releases its
pipes. An explicit background-command option permits the SSH master launch to finish
on parent exit after a bounded output-drain period. Ordinary commands still wait
for complete trailing output. Password setup verifies the exact owned control
socket with `ssh -O check`, and attempts scoped cleanup on startup/confirmation
failure. Review caught and fixed confirmation/cleanup exceptions that otherwise
leaked the reserved authentication attempt. Regressions include repeated failures
beyond the three-attempt limit, real descendant-held pipes, trailing output and
secret redaction. There is no process-name-wide kill or new dependency.

Actual non-root Node 22.15.0 / OpenSSH acceptance passed twice with fresh keys:
**64/64 checks each**. It exercised the real Phi coordinator, not a mock:

- First-use fingerprint inspection, explicit test confirmation and pinned trust.
- Three wrong-password outcomes, including attempt exhaustion, then a new valid attempt.
- Passphrase-protected key generation, public-key installation, agent verification and saved config.
- A fresh key-only login, rejection without the agent, and changed-host-key rejection.
- Private file permissions and cleanup, supplemented by independent process/key checks.

The 250 ms background drain did not break master reuse in these real flows. Failed
master-close attempts remain best effort; a call to `-O exit` alone is not proof of
process absence, which is why independent process evidence is required.

probe on native Linux x64 before changing dependencies or blaming application code.
