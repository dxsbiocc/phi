## Failures retained and repaired

1. **Misleading SSH cleanup success.** The cleanup derived a socket identity without
   the launcher's HOME/agent-directory suffix. It could inspect/remove the wrong
   endpoint and claim success while the real kernel remained. Rosetta also makes
   `/proc/PID/exe` point at its translator, defeating the old executable comparison.
   Original reconnect and proxy-reconnect reports remain alongside independent
   process tables showing the mismatch; their overall cleanup is not accepted.
   The original retained kernels later expired naturally; they were not silently
   counted as promptly cleaned up.
2. Cleanup now shares the launch identity, checks same-user exact executable and
   socket/token arguments (with the observed Rosetta translator exception), fails
   on inspection errors, and records `graceful`, `term` or `kill`. Unknown executable
   or conflicting argv fails without signalling or removing the endpoint. SSH
   command failure is no longer treated as proof that a child exited.
3. **Stale plan fixture.** The original replan run timed out. Its successful child
   replies were ordinary prose, which the current completion contract correctly
   classifies as partial. A generic paused-plan check could therefore mistake a
   failed read for the intended write failure. The fixture now emits valid completion
   declarations, matches replies to actors, checks the exact initial failed step,
   and retains before/after plan states and review count on failure. The corrected
   real-kernel run passed. No product scheduler fix was justified or made.
4. **Incomplete packaging gates.** The manual Linux packaging workflow now invokes
   the existing packaged-kernel checker before uploading artifacts. Release `verify`
   now runs the existing full regression command before packaging. These workflow
   edits passed local contract tests; they have not yet executed in remote CI.

DSH supplied the platform audit and the two gate patches. Codex reviewed and
