# Phi 科研意图澄清、质控交接与下游调度实施方案

**提案 · 2026-11-19 · 首版覆盖本地受控科研分析。** 当用户的目的会改变分析方法时，Phi 应先问清楚。当一个步骤结束时，Phi 应依据实际产物判断哪些后续步骤仍有意义。首条验收链为差异表达 → 条件性富集 → 报告。即使没有显著基因，研究者也应拿到完整、可复核的差异结果，并看见富集步骤的处理理由。

## 1. 职责与接入位置

| 谁负责 | 具体责任 |
| --- | --- |
| 研究者 | 确定研究目标、比较对象和会改变解释的取舍。可以预先同意条件分支，也可以选择仅做描述性分析。 |
| Phi 主 Agent | 委派时写清本次要回答的子问题。每次收到子任务终态回报，把结果与用户原问题及已确认的修订放在一起，指出答到了哪一部分、还差什么，据此选择交付、推进已批准步骤或向用户提问。 |
| Phi-packages 领域插件 | 脚本或 wrapper 计算指标，领域 Skill 或专家解释它们在本研究设计下意味着什么。插件负责说明本分支为什么可以结束，或继续哪个分析能解决哪项不确定性，并附依据、限制与产物引用。 |
| Phi 执行器与界面 | 核验产物和硬性前提，执行主 Agent 在用户授权范围内选定的动作，按规则阻断或跳过步骤。显示处置理由，保留可回查的完整运行记录。 |

**已有基础。** Phi 已能显示带选项的问卷，计划步骤报告缺少输入时也能暂停。当前调度器允许前驱 `done` 或 `skipped` 后安排后继，因此“前一步已结束”和“后一步需要的结果确实存在”必须分别检查。这次增强现有计划、工具派发和产物记录。首版的强制保证限于已接入的计划步骤、插件脚本和 wrapper，交互式自由代码另计。[提问工具](../../src/main/agent/user-interaction-tools.ts) · [计划执行器](../../src/main/agent/plan/execution/plan-executor.ts) · [调度器](../../src/main/agent/plan/model/plan-scheduler.ts) · [产物契约](../contracts/artifact.md)

## 2. 什么时候必须问

先读用户原话、已确认的计划和可用元数据。只有**答案影响下一步能做什么或结论怎样解释，且现有证据不能唯一确定答案**时，才发起澄清。规则由所选方法声明，Phi 在计划审阅和受控派发前执行。研究者明确给出的信息可直接引用，自动模式下同样保留这一检查。

| 触发条件 | Phi 应如何处理 |
| --- | --- |
| 同一请求有多种合理目标，所需方法不同 | “分析这批单细胞数据”可能指细胞图谱、细胞组成或组间表达。可先只读检查文件、样本表和数据层，然后让用户选择目标；正式统计和推断等待选择。 |
| 目标明确，但总体、实验单位、配对或比较方向有实质歧义 | 利用表中真实存在的列和分组提问。例如同一供体有两次采样时，询问是否比较同一人的前后变化。数据与用户描述冲突时展示冲突行或摘要，请其补映射或修订目标。列名排序和文件名都不能确立参照组。 |
| 质控提出需要研究者取舍的警告 | 说明实际指标、哪些步骤受影响以及继续后的限制；让用户选择保留样本并带限制继续、查看详情后决定或结束该分支。排除样本、改组、改阈值或改主要方法须形成有理由的新修订。 |
| 下一步回答新问题或超出已确认计划 | 展示新增方法回答什么问题、使用什么输入。用户选择新增后更新计划；原计划已明确批准且前提满足的条件分支无需再问。 |
| 方法前提已证实不成立 | 立即说明并阻断该推断。只有存在有意义的下一步时才询问，例如“补充独立样本”或“仅查看描述性汇总”。界面不提供忽略硬性错误的选项。 |

**提问示例。** 用户说“分析治疗前后的单细胞数据”。Phi 可以问：“这批样本含治疗前和治疗后两个时间点。你希望先回答哪个问题？”选项为“哪些细胞类型的比例发生变化”“指定细胞类型内哪些基因发生变化”“先看图谱与质控”，并保留自定义回答。若用户已明确要求第二项且已指定 T 细胞，只核对尚缺的供体配对信息。供体信息还是未知时，可以选择“提供供体与样本对应表”或“本轮仅做描述性汇总”。

**答案如何生效。** 每题沿用现有的 2–4 个带说明选项及自由输入。可从文件确定的格式、已确认的映射和预先批准的分支直接复用。需要比较的步骤保存目标、分析对象、实验单位、目标组与参照组、配对或协变量、选用方法及阈值；只要求该方法用到的字段。每项注明来源（用户原话或回答、产物观测、待确认）。供体身份等实验事实仍须与文件核对。先持久化待答问题，再打开界面；取消、空答和关闭窗口都没有授权效果，重开可继续回答原题。图谱和描述性任务无需填写差异分析字段。[交互约定](../../src/shared/agentInteractionTypes.ts) · [问卷等待逻辑](../../src/main/agent/user-interaction.ts)

## 3. 插件怎样把质控交给 Phi

**包在安装时声明规则，运行时交付事实。** Phi 在现有包契约中增加可选的版本化科研声明，并校验后固化到本次运行。生产者声明能提供哪些指标和产物；消费者声明会使用哪些证据、什么条件允许执行、哪种有效空结果可以跳过。首版比较器只需支持存在性、枚举匹配和数值比较。统计方法特有的计算放在包内，例如样本按供体去重、按已选方向统计上调基因数。各包通过有版本的指标标识和产物角色对接。

**传输。** 脚本工具在已有 JSON 返回值里给出可选的 `qcReport` 项目相对路径；wrapper 在清单中声明同一报告的输出角色，或由已声明的提取器从完成的结果表生成报告。Phi 在生产者结束后从实际执行位置读取完整报告与源产物，将验证记录写入运行目录，向计划只传引用和摘要。单独读取聊天文本、日志中的“QC passed”或界面预览均不能生成可执行的判定。[脚本工具结果入口](../../src/main/agent/content/script-tools.ts) · [组合 wrapper 清单类型](../../src/shared/wrapperCompositionManifestTypes.ts) · [Scientific Trust 的输出检查与指标提取](scientific-trust-implementation.md)

以下是拟议的生产者报告样例，数值来自第 5 节的固定验收表。路径和输出角色由 Phi 对照本次运行的实际产物解析。

```json
{
  "schemaVersion": 1,
  "method": "local/modules/differential-expression-deseq2",
  "comparison": { "target": "treated", "reference": "control" },
  "selection": { "adjustedPBelow": 0.05, "absoluteLog2FCAtLeast": 1 },
  "source": { "output": "results", "path": "de/treated_vs_control.deseq2.results.tsv" },
  "metrics": [
    { "id": "de.evaluable_genes", "status": "observed", "value": 3, "unit": "genes" },
    { "id": "de.selected_genes", "status": "observed", "value": 0, "unit": "genes" }
  ]
}
```

**接收与校验。** Phi 从执行上下文补齐项目、运行、步骤、执行位置、包与规则版本，并记录输入、结果表和本次意图修订的指纹。先检查 schema、项目路径边界、产物归属、比较方向、必需列和合法值，再用包内已固定版本的提取规则复算关键计数。首版计数单位为唯一基因 ID；同一 ID 多行且没有声明处理规则时，报告无法评估。缺失或不可计算的指标用 `status: "unknown"` 加原因，省略 `value`；损坏、与源表冲突或来自旧运行的报告标记为无效。旧包和历史运行可继续查看；新步骤若要求未提供的证据，就显示缺什么，可重建证据时先重建。普通工具的成功返回只表示工具执行完成。

**消费者规则示例。** ORA 声明候选集来自哪一步、哪个比较和哪个筛选方向。总候选列表使用上例的 `de.selected_genes`；若仅检验上调基因，包须另行交付对应方向的候选集及计数。在同一次比较的有效主表上，先确认 `de.evaluable_genes > 0`。随后，所选列表计数为 0 就产生 `empty_candidate_list` 并跳过；大于 0 才检查候选集、背景、注释和可映射基因。预排序 GSEA 单独声明排序证据。消费者只声明证据和适用条件，Phi 将条件映射到下节的执行动作。

### 每次子任务结束时怎样交接

沿用现有子 Agent 完成报告协议，为科研任务增加可选的结构化摘要。Phi 在委派时绑定原问题修订、子问题和运行标识，回收时用同一标识对齐。执行状态沿用现有的完成、部分完成、阻塞或失败；它只描述子任务的执行情况。[子 Agent 报告协议](../../src/main/agent/agents/report.ts)

| 子任务回报内容 | 示例 |
| --- | --- |
| 本次回答的子问题和直接结果 | “治疗组相对对照组，有哪些基因达到预设差异阈值？3 个基因可评估，0 个达到阈值。” |
| 领域解释与边界 | “候选列表为空，依赖该列表的 ORA 应结束。本次基因筛选未检验通路成员是否整体偏向排序的一端。” |
| 继续或结束的理由 | “若目标只涉及候选基因，现有结果足够交付。若目标涉及通路整体偏移，下一步需要有效的全基因排序，并核实这项比较是否已获批准。” |
| 证据与缺口 | 引用本次运行的完整差异表、已核验的 QC 记录；列明缺少的输入，或指出已具备的证据。执行失败也回报原因和仍可用的产物。 |

**主 Agent 如何判断答案与问题的适配度。** 每次回报都更新“原问题及已确认约束｜目前能支持的答案｜尚未回答之处｜证据引用”。判断对象包括分析人群、实验单位、比较方向及结论层级。例如，细胞组成变化回答不了同类细胞内的表达变化。针对每个子问题记录“已回答、部分回答、未回答或证据冲突”及一句理由。独立子任务的结果并列归入相应子问题；冲突的结论保留双方证据。用户修订问题后，旧回报按原修订归档，只有仍适用的证据才带入当前答案。

| 对照原问题后的情况 | 主 Agent 的下一步 |
| --- | --- |
| 证据已足以回答，或在当前数据下只能给出明确的局限 | 交付已核验的答案并标明覆盖范围。有效的零结果也可以完成任务。 |
| 仍有具体缺口，领域插件指出了能缩小缺口的方法，且计划已批准 | 推进对应步骤，由执行器复核其输入和 QC。若只是等待已派发的并行子任务，保留缺口，待其回报后再判断。 |
| 答案取决于用户意图、补充数据或新的研究取舍 | 说明“已经知道什么、还差什么、选择会改变什么”，只询问该决定。遇到技术失败或证据冲突时，先按引用检查能够核验的部分。 |

**主上下文如何保持精简。** 主 Agent 每次读取原问题、相关子问题的最新摘要、必要限制和证据引用。后续更新替换同一子问题的工作摘要，原始日志、全量结果表和历次尝试保留在子运行或产物目录。数字矛盾、引用失效或用户要求明细时，按引用读取对应产物，核清后只带回影响决定的事实。前台返回、后台完成通知、主动等待和计划步骤共用这份精简视图，同一次子运行只处理一次。旧插件可沿用文本回报；若无法提取足够依据，标为证据不足。现有文本截断可保留作长度上限，不能替代按问题选择内容。[前台返回](../../src/main/agent/agents/tool.ts) · [后台完成通知](../../src/main/agent/agents/run-continue.ts) · [主动等待](../../src/main/agent/agents/run-tools.ts) · [计划上下游摘要](../../src/main/agent/plan/execution/step-prompt.ts)

## 4. Phi 怎样决定继续、暂停或跳过

对每个受控消费者依次检查：① 操作是否属于明确的研究意图；② 产生证据的运行、输入、输出和规则版本是否有效；③ 方法的硬性前提；④ 已批准的条件分支；⑤ 影响解读且尚未处理的警告。**仅对该判断实际需要的证据求值。** 例如已经验证候选列表为空，就足以跳过条件性 ORA，此时无需追问 ORA 背景集。证据损坏或来源不明时，不能进入“有效空列表”分支。

| 证据或事件 | 调度动作 | 用户看到什么 |
| --- | --- | --- |
| 意图明确，必需证据通过，步骤在原计划内 | **继续**，按既有权限派发；普通信息性提示随结果显示 | 当前执行的方法和依据，无重复确认 |
| 缺研究者才能给出的答案，或警告涉及真实可选的科研取舍 | **暂停并提问**；记录 `needs_input` 和受影响步骤 | 未知项或实测警告、选择后果、已有产物；回答后重新校验 |
| 已知设计不成立、主结果损坏、所需验证失败 | **阻断并暂停**；记录 `step_failed` 和科学原因，停止自动重试。对临时读取失败可沿用有界恢复，恢复前保持待核验 | 失败证据、可修复项，以及仍可交付的描述性结果 |
| 条件分支的输入已核验，且确实不适用（如 ORA 候选列表为空） | **跳过**，记录 `skipped`、规则和证据，不启动工具。若这是用户唯一要求的产出，明确回报该产出未能生成 | 跳过理由、可查看的结果；已批准且输入齐备的报告仍可生成 |

**运行时落点。** 尚无计划的直接请求，将待答项绑定会话、当前请求及执行位置；进入计划时沿用同一份已确认意图。计划审阅时检查当前已知条件；上游每次交付约定的质控结果即更新界面。在 `PlanExecutor.launch()` 建立派发身份或调用 `runner.start()` **之前**再次判断。在受控脚本工具和 wrapper 实际提交处共用同一判定，覆盖直接调用、子 Agent 调用与计划重试。首版按已登记的实际工具或方法识别受控推断；即使计划漏写规则、主 Agent 走直接模式，也应进入同一个意图检查。普通只读查看按原路径执行。多阶段工具如需在长计算中途停下，应拆出能及时交付 QC 的阶段；只有终点报告的工具只能在完成当步后拦住下一步。

**计划状态与恢复。** 自动跳过仅结束对应分支。现有计划的暂停是计划级的；首版等待回答或修复时停止派发新步骤，已启动的独立工作可按现有策略收尾，取消仍遵循现有停止语义。报告步骤可接受“富集已跳过”的记录；需要富集结果表的绘图步骤则随该分支跳过。未知来源或缺少必需产物不能冒充有依据的分支跳过。[计划状态归约](../../src/main/agent/plan/model/plan-run-state.ts) · [失败重试策略](../../src/main/agent/plan/model/failure-policy.ts)

为启动前的等待、阻断和科学跳过增加专用事件；现有“运行中的步骤失败”事件要求步骤已启动。待答或被阻断的步骤应维持零次新尝试、无子运行 ID、无作业提交。问题、答案和处置记录绑定计划修订、步骤、规则和证据指纹；先持久化再展示或派发。重启时恢复待答项，重复点击只生效一次。补充元数据、替换同路径文件、调整阈值或升级规则后，旧证据保留可读，重新验证受影响的后继。科研信息缺失与远程派发回执未知使用各自的状态。首版远程未接入验证时显示“当前执行端尚无法核验”。[计划存储](../../src/main/agent/plan/persistence/plan-run-store.ts)

## 5. 验收案例：差异表达之后是否运行富集

**固定输入与口径。** 假设样本设计和差异分析已核验，比较为治疗组相对于对照组，预设阈值为 `padj < 0.05` 且 `abs(log2FoldChange) >= 1`。此例中“可评估”指 ID 有效、用于该筛选的调整后 P 值和效应量均有效；单个 NA 从该分母排除并记录。主要差异表允许部分 NA，筛选后的候选表允许只有表头。读取失败、全部不可评估和真正零命中应产生不同结果。

| 基因 | padj | log2FoldChange | 按本次规则 |
| --- | ---: | ---: | --- |
| G1 | 0.050 | 2.0 | 可评估，未达到严格小于的 P 值阈值 |
| G2 | 0.040 | 0.8 | 可评估，未达到效应量阈值 |
| G3 | 0.200 | -1.5 | 可评估，未达到 P 值阈值 |
| G4 | NA | 1.4 | 排除并记原因 |

**主验收。** 已批准计划规定“若有候选基因，做过度代表分析（ORA），随后生成报告”。使用上表，应观测到差异步骤完成、3 个可评估基因、0 个命中、ORA 派发次数为 0、依赖 ORA 的图未生成、报告完成。界面在跳过当步即显示原因，报告中的 3 和 0 能由主表复算。建议文案为“治疗组相对于对照组，3 个基因可按预设阈值评估，0 个达到阈值。已跳过需要候选基因列表的 ORA。可查看完整差异表和样本质控。” 结论只覆盖本次比较及筛选条件。

| 配套验收 | 预期行为与核对证据 |
| --- | --- |
| 同一回报，两个原问题 | 使用上表的同一条“3 个可评估、0 个命中”回报。问“哪些基因达到阈值”时直接交付。问“通路是否整体偏移”时标为尚未回答；有效排序及已批准 GSEA 俱备时推进，若新增分析需要用户决定则说明理由并提问。两者的 ORA 派发均为 0。 |
| 主上下文与回报顺序 | 在子运行日志中加入与原问题无关的长表和唯一标记；检查前台、后台及计划路径实际交给主 Agent 的内容：有原问题、结果、限制、依据和未答项，无该标记或长表正文；凭引用仍能打开原件。重放同一回报不重复触发动作，并行回报倒序到达不覆盖另一子问题的答案。 |
| 正常阳性对照 | 用同一阈值、适量可映射的命中基因和匹配的背景集。ORA 只启动一次，产出表可追溯到候选集、背景集和注释版本。边界单测把 G1 改为 `padj=0.049`，候选数应从 0 变 1。 |
| 结果无法评估 | 分别移除主表、删除必需列、令全部 padj 为 NA。界面分别提示缺失、结构错误或无法按该阈值评估，保留能打开的材料；ORA 派发次数为 0，报告不填“0 个显著”。在此项用例中不提供独立有效的排序证据，GSEA 也不启动。样本映射已知错误时应更早在差异步骤前阻断。 |
| 有候选，但背景或映射有问题 | 可修复的背景集缺失先请求补充；物种不兼容或显著基因全部无法映射，说明具体原因。ORA 不派发，结果页保留差异命中数，不能把映射失败描述为零命中。 |
| 已预先批准预排序 GSEA | GSEA 使用有效的全基因排序。以另一个规模合适的固定数据集验证排序统计量、方向、基因 ID、基因集版本和有效重叠均满足包规则。即使差异筛选命中为 0，ORA 跳过，GSEA 仍执行一次。 |
| 原计划仅含 ORA，新增 GSEA | Phi 可说明 GSEA 回答“某基因集是否偏向排序的一端”。只想交付原结果的用户无需处理额外提问；用户要新增这项分析时，审阅新分支后才派发。取消、无回答或排名无效时，GSEA 启动次数为 0；原筛选阈值保持可追溯。 |
| 重启、重试与换表 | 在待答时重启，重新展示同一问题；旧答案或旧 QC 与新表指纹不符时不得放行。对同一有效答案重复提交和重开计划都不会重复启动 ORA，也不会把跳过改写成运行成功。 |

ORA 使用候选基因和合适的参照背景；预排序 GSEA 使用排序列表。两个方法应分别声明前提和可回答的问题。[Gene Ontology 富集分析说明](https://geneontology.org/docs/go-enrichment-analysis/) · [GSEA 用户指南](https://docs.gsea-msigdb.org/GSEA/GSEA_User_Guide/)

## 6. 可独立验收的开发顺序

| 交付批次 | Phi 侧改动 | 合入证据 |
| --- | --- | --- |
| ① 意图与提问 | 在计划草稿和受控工具入口登记必需的意图字段，复用问卷；扩展答案绑定和持久化。计划审阅中展示用户原话、已知项和待决定项。 | 用“帮我分析这批数据”和完整指定目标的请求做对照。前者只读探查、显示有效选项，回答前零推断调用；后者不重复问。取消、重开和中英文切换保留同一决策身份。 |
| ② QC 契约与首个生产者 | Phi 增加可选报告 schema、加载校验、运行侧存证与结构化摘要。Phi-packages 只需配合交付一个固定版本的差异分析生产者和富集消费者声明。 | 主程序和包使用同一组正负样例。校验真实零值、NA、错误版本、文件换名或替换、损坏和缺报告；旧运行可读。要求强制检查的包声明最低 Phi 版本；旧客户端遇到该包时应提示不兼容。 |
| ③ 子任务回报与下游调度 | 扩展子 Agent 报告协议和各完成入口。在科研计划的关键步骤收回结果后，先保存主 Agent 对问题的判断，再派发依赖这一判断的后继。把原问题修订、精简回报与所选动作一并持久化，并贯通执行器、kernel 和步骤界面。 | 对直接调用、计划、子 Agent、重试分别记录真实派发次数。用同一回报验证不同原问题的处置，检查长日志隔离、重复回报、硬性阻断和跳过传播；受阻时没有子作业。 |
| ④ 从实际包到报告 | 锁定 Phi 和 Phi-packages 测试版本，通过正常安装、启用和计划入口运行第 5 节案例。保留运行记录、原始表、报告及下游启动清单。 | 第 5 节各行分别通过；独立读取原始表复算报告数字。把正常输入被误阻断、无效输入被放行、科学跳过和未运行分别计数。 |
