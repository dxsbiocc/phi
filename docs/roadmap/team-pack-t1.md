## 模型子 key 的格式

团队包的资源密文是全体成员共用一份；模型子 key 每人不同，不能放进共用密文。每次发布为每名拿到子 key 的成员单独写一个 `releases/<n>/grants/<随机名>.age`，只加密给该成员；文件名随机，manifest 签名覆盖每个文件的哈希。成员拉取时逐个尝试解密（有上限），解出的内容再校验 `teamId` 与版本。子 key 只在内存中交给调用方，由调用方写入凭据存储；拉取本身不落明文。

这会暴露"拿到子 key 的成员人数"，与 L0 已接受的"大致接收方数量"同级。

## T1-1 已完成（2026-11-04）

- `latest.json` 已合并为 `{pointer, signature}` 单文件，签名覆盖规范化的 `pointer` 字节；原型旧双文件格式不再读取或写入。
- 团队签名私钥和成员 age 身份通过注入的 `SafeStorageLike` 加密落盘，安全存储不可用时拒绝保存；支持 age scrypt 口令备份及团队/成员一致性校验。
- manifest 签名覆盖每名成员独立的 grant 文件名、大小和哈希；拉取在提交状态前核验全部 grant，只返回本成员可解出的模型配置。
- 管理员 roster 原子保存成员软删除历史和发布成员快照。`withdrawnReleases` 为累积快照；最新版本撤回自身时拉取以 `RELEASE_WITHDRAWN` 安全失败且不提交状态。

## T1-2～T1-4 已完成（2026-11-04）

- 成员侧：`team` 来源登记于 `<agentDir>/team-sources.json`，启动时与每 6 小时拉取（仅在已登记来源时启动）。子 key 经 `ModelRuntime` 写入；只有该 provider 仅剩一条且 id 与 key 指纹都与团队记录相符时才删除。
- 管理员侧：成员 grant 用钥匙串加密存于 `model-grants.enc`，每次发布（含撤回）沿用。
- 界面：设置中新增"团队"页。Electron 主进程不能打包只能在 bun 下运行的模块，由 `tests/team-pack-main-imports.test.ts` 守护。

## T1-6 已完成（2026-11-04）

- 加密 `inner.json` 带 `announcements`（最近 20 条，每条 ≤4000 字符纯文本）与按 `type:id` 索引的 `resources`（`sharing: team-only | forwardable`，可选 `originalSource`）。

## T1-7 已完成（2026-11-04）

- 团队密钥 v2 增加 age 投稿收件身份，随团队备份导出；收件公钥只放在签名加密的 `inner.json`，成员拉取后存入来源状态，不信任 `team.json`。
- 成员身份 v2 增加 Ed25519 签名密钥；公钥改为组合字符串 `phi-member-v1.<payload>`，旧的纯 age recipient 仍可登记但不能投稿，可用组合公钥原地补登记。
- 投稿包：签名清单 `submission.json` + `submission.sig.json` + 小型 `registry/`，只加密给收件公钥，上限 32 MiB。
- 送达：可写文件夹来源写到 `submissions/<成员签名指纹>/<submissionId>.age`，否则导出 `.phi-submission`。发布与拉取都忽略 `submissions/`。
- 审核：解密、核对在册未移除成员、签名、teamId、哈希与包格式；接受后进入管理员目录 `pending-submissions/<submissionId>/`，下次发布默认勾选并标注投稿成员，发布后消费。不会自动安装到管理员本机。
