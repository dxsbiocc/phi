## Early-quit crash found during acceptance

The failed first Notebook setup attempt exposed a real native crash, independently
matched to the OS crash report by PID and timestamp. A separate no-import/no-guard
reproduction confirmed two SIGSEGV exits when quitting immediately or after 100 ms,
while a 3-second control exited normally. The older baseline candidate also crashed
at 100 ms; another baseline attempt hung and required cleanup. These results are
not evidence of a new cancellation regression.

An instrumented diagnostic recorded `before-quit`, `will-quit`, and `quit`, then a
new `browser-window-created` event 164 ms later; the process hung and was explicitly
cleaned up. The async startup continuation could run after shutdown and reset the
window cleanup state. DSH traced this sequence and supplied the narrow guard patch.
Codex added tests executing the actual entrypoint callback (3 failures before the
fix, then passing), and independent review prompted additional guards for late
splash showing/fading and recovery-dialog callbacks.

The fix reuses `mainWindowRetention.isQuitting`; it adds no parallel shutdown state
or new dependency. Two actual splash tests first failed, then passed. Final related
coverage is 34 passing startup/quit checks, and 307 passing main integration tests;
application/test type checks, lint (0 errors / 1,374 existing warnings), and the
production build passed again after the final changes. The earlier full-suite
8,031-pass count predates this newly discovered fix and is not represented as a
second fresh full-suite run.

Split-or-keep: the large existing `src/main/index.ts` remains legacy architecture
debt. These small lifecycle guards stay beside the existing startup/quit wiring;
a broad entrypoint split would expand this acceptance repair. No renderer feature
structure changed.
