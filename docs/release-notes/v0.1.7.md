## What's Changed

### Plans stop, recover, and use plugin tools
- Stopping a plan now also ends a replan turn that is still drafting. A stopped or paused plan shows the matching stop or pause state, and stale replan errors are cleared.
- Updating a content package no longer interrupts a running plan step or background agent. The pending refresh waits for that work instead of cancelling it.
- Quitting Phi while a step is running records the step as interrupted and pauses the plan instead of reporting a failed attempt or starting an automatic retry. The interrupted state is kept for recovery after a restart.
- Plan steps can use installed plugin script tools and plugin skills. A step that needs a managed environment now asks for confirmation in its conversation instead of being treated as declined.
- Stopping a plan prevents remaining steps from starting and requests cancellation of active steps. It does not roll back files already written.

### Plugin installs, messages, and content updates
- Plugin installs and upgrades now run as background jobs. You can close the catalog while one runs and follow it in Background Jobs; a second update for the same plugin is blocked until the running one finishes.
- Package and app updates appear in a Messages panel behind the bell in the top-right. Each package update is a separate message with an unread dot; opening it marks it read.
- The package update dialog shows release notes per version, with Latest and Breaking labels and typed New, Improved, and Fixed changes.
- Updating a content package no longer deletes shared managed environments such as `phi-r`. Automatic cleanup keeps them; explicit cleanup in Settings still removes them. The managed `phi-r` environment now includes `ape`, `ggtree`, and `tidytree` for the tree visualization templates.

### Background jobs and workflow progress
- A retried workflow step counts once, by its latest attempt, for progress, notifications, and job history; repeated attempts do not count as separate steps. Clearing finished jobs keeps the record of an unfinished workflow.
- Background subagent runs remain listed while running and after a restart. Background job cards name the operation and its target and use a plugin's own icon.
- Reopening a session no longer announces jobs that had already finished.

### Long sessions and message evidence
- Agent runs keep unique IDs across a restart, so a conversation that reused one can reopen instead of failing.
- When an automatic retry succeeds, only the request errors from the recovered attempts are removed; one retry can recover several failed requests. Approval denials and other independent failures stay visible, both live and in replayed history.
- A local image path inside a sentence or list item now renders as an inline file chip, so its name stays with the text. A path on its own still opens the image preview.
- Specialist agents inherit the project boundary and route approvals through their run. Read-only file tools can inspect Phi's installed packages without a prompt.

### Notebook startup

- Notebook sessions now wait for the local Jupyter server to answer a health check. A startup URL printed before the server is listening no longer enables premature connection attempts; delayed startup announcements still receive a bounded check.

### Internal beta notes
Phi 0.1.7 is an internal beta, not a stable release. Packages target macOS arm64, Linux x64, and Windows x64; clean-machine acceptance has not been completed for every target.

- macOS builds for this beta are ad-hoc signed, without formal Developer ID notarization. Gatekeeper asks you to allow the app once under **System Settings → Privacy & Security**.
- Windows has no code signing configured, so SmartScreen may warn about the unsigned installer. Windows x64 remains a preview target.
- Updates are manual: install the new build over the old one. Your data stays in `~/.phi`.

- 更新内容包不再打断正在运行的计划步骤或后台智能体；更新会延后处理，而不是取消当前工作。
- 计划步骤现在可以使用已安装插件的脚本工具和技能；需要构建托管环境时会在对话中询问确认。

- 更新内容包会保留 `phi-r` 等共享托管环境；`phi-r` 新增 `ape`、`ggtree`、`tidytree`，用于树形可视化模板。
- 工作流重试步骤按最新一次计一次进度、通知和作业历史，重复尝试不会计为独立步骤；清理已结束作业时，未完成工作流的记录仍保留。

- 句子中的图片路径保持为文件标签。
- Notebook 会等待本地 Jupyter 服务实际响应健康检查后再建立连接，不再仅凭启动地址日志判断就绪；迟到的启动地址仍会获得一次有界检查。
- 停止计划不会回滚已经写入的文件。
- 这是内测版本，打包目标为 macOS arm64、Linux x64 和 Windows x64；并非所有目标都完成了干净环境实机验收。
- macOS 使用 ad-hoc 签名，没有正式 Developer ID 公证；Windows 未配置代码签名。更新需手动安装，数据保留在 `~/.phi`。
