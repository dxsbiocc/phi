## What's Changed

### Missing tools: Phi asks instead of improvising
- When a Wrapper run needs Nextflow, Java, Jupyter, or a container runtime (Docker, Singularity/Apptainer, Podman) that Phi cannot find, the conversation now pauses on a card. You can pick a candidate Phi found, enter an environment folder or the absolute path of the program, or have Phi create its own managed micromamba environment (`phi-nextflow`: Nextflow with Java 17+).
- Nothing is installed unless you choose to. If a path is rejected, the card asks again and says why (not executable, no version reported, Java too old, and so on).
- Candidates now include Conda environments registered in `~/.conda/environments.txt`, so Phi finds them even when `conda` is not on the server's login `PATH`.
- The Wrapper specialist no longer installs tools, edits shell profiles such as `~/.bashrc`, or creates shims when a server is not ready. It stops and reports what is missing.

### Wrapper runs
- **Inputs must now be given explicitly.** Earlier versions could fill an omitted input from the Wrapper's `params.json`, which holds nf-core test data (often a GitHub URL). A run could then analyse that test data, or hang while downloading it. Only output and option defaults are inherited now.
- Nextflow runs on the Java from its own environment when you point Phi at a Conda env. Before, it could fall back to an older system Java and fail.
- Wrapper catalog search and inspection work in remote projects.
- Background Jobs: a retried step counts once in its workflow, so a workflow no longer shows more steps done than it has (for example "5/4"). Workflow steps show only the tool name and status.

### Other
- Remote environment settings: you can set a Singularity/Apptainer path, and Phi checks that it points to `singularity` or `apptainer`.
- Shell commands that redirect to `/dev/null` are no longer treated as writes outside the project.
- README: the Wrapper section explains how tools are composed into workflows, and shows a real run on a GPU server.
