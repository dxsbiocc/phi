# Phi 发表计划与 Nature 系列论文参照

修订日期：2026-11-17。项目事实沿用源码基线 `72c6d4fa`、版本 `0.1.7` 的审计。本次按已发表于 Nature、Nature Methods、Nature Biotechnology 和 Nature Medicine 的相关论文，修订研究内容、对照设计、论文结构及投入顺序。

**建议以 Nature Methods Article 的研究组织方式准备方法论文：一个清楚的方法学问题、可拆解的机制、公平的跨任务比较，以及贯穿全文的真实研究案例。** 拟研究的问题收紧为：当单个工具能够正确运行时，怎样发现并阻止跨步骤的样本、参考版本和数据语义不一致，避免得到形式完整但科学上不合格的结果。能否形成足够新颖且普适的方法贡献，仍需对照实验回答；这不是已达到该期刊标准的判断。

本文补充并校正 [11月论文定位草稿](paper-positioning-2026-11.md)。现有正确性修复继续沿用 [内测路线图](../roadmap/internal-beta-implementation.md) 的 Scientific Trust；新增的跨步骤科学一致性机制和研究评测是拟议研究增量，需单独形成实现与测试规格，不能视为已包含在 T1–T8 或已完成的能力。

具体开发安排见[论文开发任务与实验验收](../roadmap/publication-development-tasks.md)：25项任务的优先级、依赖、实现落点、论文实验和验收标准以该清单跟踪；本文保留研究问题和发表论证。

正文起稿见 [Phi 论文大纲](phi-manuscript-outline.md)，包含摘要开头、引言段落和五张主图的证据安排。

读取范围：Paper2Agent 与 SPARK 核对了 Nature 官方可检索正文、相关 Methods 和图注；Robin、SpatialData 核对正文与 Methods；Nextflow 使用作者团队存档的正式全文。CellVoyager 和 Virtual Lab 的依据限于正式摘要、主图目录及可用性/贡献声明，不据此断言未读到的对照细节。nf-core 依据主文开头、图注及官方补充材料，未据受限正文重建完整段落顺序。文末给出书目和补充来源。

由此提炼两种适用结构。方法路线是“具体瓶颈 → 方法原理 → 对照表现 → 失效机制 → 真实用途和独立复现”；发现路线是“重要问题 → 候选假设 → 数据或实验反馈 → 独立验证 → 生物学解释”。这是本计划的组织建议，不是 Nature 系列唯一的写法。

## 项目已经具备什么

按论文需要理解 Phi，可分为五层：项目和会话管理；计划与专用智能体；Notebook 与固定 Wrapper 两种执行方式；本地和 SSH/HPC 计算；产物、日志和运行记录。界面、插件目录和工具数量是使用基础，论文贡献需要落到这些机制改善了什么可测量的问题。

| 层面         | 当前证据                                                                          | 可以写到什么程度                                                             |
| ------------ | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 固定科学流程 | Wrapper 声明参数、输入与输出，使用 Nextflow；已有类型、范围、路径和部分防混样检查 | 可以描述设计与实现；上游 nf-core 来源不等于 Phi 适配和流程拼接已得到科学验证 |
| 探索分析     | 托管 Python/R 环境、Notebook 执行和保存；已有真实模型生成并执行小型数据分析的记录 | 可以证明探索链路可用；尚不能量化组学分析正确率                               |
| 计划执行     | 步骤、依赖、重试、中断与恢复；host-origin 子任务要求结构化完成报告                | 可以描述任务控制；结构化报告不能替代独立产物验收                             |
| 远程与集群   | detached SSH、Slurm 控制器、容器/Conda 路径；远程运行快照和重启接管               | 可以描述已实现机制和特定历史实跑；当前版本的端到端科学任务仍需重复验证       |

## 两条论文路线的比较

| 维度                 | 方法与平台论文                                                 | 生物医学应用论文                                             |
| -------------------- | -------------------------------------------------------------- | ------------------------------------------------------------ |
| 主问题               | 如何让科学智能体更可靠地完成长流程，并提供可复核的结果         | 某疾病、细胞状态或分子机制中，发现了什么此前未知且可信的关系 |
| 主贡献               | 执行与验收机制、公开任务集、同模型对照、跨场景证据             | 新发现、独立验证、机制或功能证据；Phi 是研究手段             |
| 与现状距离           | 较近，现有平台可直接用于实验建设                               | 较远，本次材料中未见完整的新发现及验证链                     |
| 最关键补充           | 科学评分、输入与输出验证、运行证据、基准与消融                 | 明确假设、患者/供体级数据、独立队列、领域合作与适配的验证    |
| 合理主结果           | 相同模型和资源下减少错误成功报告，并改善正确产物比例或人工成本 | 在独立数据中重复的效应；如主张机制，则增加相应干预证据       |
| 最大风险             | 被评价为已有工具集成；收益仅来自某个模型、更多预算或现成脚本   | 只有公共数据再分析、关联堆叠或已知结论复现，缺乏新意         |
| 提升论文竞争力的方式 | 可推广的机制、独立评测、跨模型效果、故障诊断、外部复现         | 问题的重要性、发现的独特性、验证的深度与可信度               |

推荐顺序是“平台论文为主，真实应用为证据”。如果某个案例形成可独立复现的新发现，再发展成应用论文；避免让第一篇同时承担通用平台、多个疾病机制和蛋白设计三种过大的主张。

拟采用 Nature Methods Article 作为主写作模板；只有主要贡献变成可广泛复用的任务/数据集合时，才重新评估 Resource 路线。该刊明确要求方法论文提供性能、可复现性、通用性和发现新生物学潜力的强验证，并未把报告新生物学发现或湿实验设为所有方法论文的统一条件。[文章类型](https://www.nature.com/nmeth/content)、[编辑部说明](https://www.nature.com/articles/s41592-020-0927-4)。

Nature 主刊的发现型案例用来校准科学问题和证据深度，不作为仅增加实验数量就能达到的目标。Nextflow、nf-core 的历史 Correspondence 不能当成今天完整 Article 的篇幅或创新尺度；SpatialData 的 Brief Communication 也不应与长篇 Article 混用。先取得研究结果，再据贡献类型判断适合的期刊与文章类型。

## 论文需要回答的研究问题

把“可靠执行”拆成三个可证伪的问题，并明确区别于单工具测试和已有工作流运行器。

1. **跨步骤科学一致性检查是否提供超出单工具验证的收益？** 在每个工具都能正常执行、输出格式也正确时，检查样本身份、参考版本、原始计数/标准化值等数据语义是否保持一致。比较科学不合格结果被报告成功的频率，同时报告正常任务误阻断和无法判断的比例。
2. **这种收益能否推广到未参与开发的任务，而不牺牲探索能力？** 固定底座模型和资源，比较自由编码、经过验证的工具集合、完整 Phi；保留新数据与新步骤组合，测试机制消融及性能代价。
3. **这些机制是否改善真实研究与独立复现？** 在一个预先定义的组学问题上，记录方法选择、人工干预、结论依据和负结果；由第二团队或独立环境重跑，并测试故障后是否产生重复计算或不一致的下游产物。

“记录完整”“数值一致”“科学结论成立”是三个不同终点。文件存在是结构检查；数值达到预定容差是分析验证；生物学解释还需要研究设计和独立证据。

Paper2Agent 已将原方法封装为经测试的工具，并固定执行环境；CellVoyager 已覆盖 Notebook 中的自主单细胞探索。因此，Phi 不能把固定工具、Notebook 或多智能体本身作为主要创新。拟研究的增量是**把科学分析上下文作为步骤衔接的显式约束，检验这一机制是否减少单工具测试无法发现的错误**。现有文献尚不足以证明这一增量独有；需要在最近邻系统的共同可执行任务上实测。[Paper2Agent](https://www.nature.com/articles/s41586-026-11044-y)、[CellVoyager](https://www.nature.com/articles/s41592-026-03029-6)。

最小研究原型仅在现有运行/产物记录中表示样本及供体身份、物种与参考版本、数据单位或变换状态，以及有限的前置/后置检查。先覆盖 RNA-seq 的几个明确边界，复用既有验证器；不建设通用本体或新的执行内核。元数据缺失时返回未知并求助，不能猜测成通过。受影响产物及其下游需重新验证；不得借此自动改变用户已确认的科学问题或分组设计。

这仍可能只带来有限工程收益。若它只检出人为设置的明显错误、在自然失败或保留任务上没有增益，应收窄论文为实用软件/评测贡献，而不是继续强化方法创新措辞。

## 最值得补充的应用场景

应用组织改为“一个技术基线、一个贯穿的生物学问题、一个保留的泛化场景”。每个应用都写清输入、系统必须做出的选择、预设终点，以及何种结果会否定最初解释；不以接入三类工具作为完成标准。

### 技术基线 从原始读段到可复核的 RNA-seq 结果

串起 FASTQ 清单、FastQC/fastp、比对或定量、差异表达、通路结果和 Notebook 报告，尽量复用现有 Wrapper。选有公开原始数据和明确参考分析的研究，固定参考序列、注释、对比和统计方法。

论文价值来自完整链路的数值核对和错误处理：定量结果、效应方向、差异基因集合、通路结果分别验收。除缺失配对或空输出外，增加“格式正确但参考版本不一致”“计数与变换后矩阵混用”等边界错误，与没有这些错误的匹配输入成对评测。通路富集记录背景基因集和多重检验规则。该案例证明方法行为，不称为新生物学发现。

### 主应用 一个细胞程序或治疗反应问题的独立验证

建议围绕一个明确问题，例如“某细胞程序与治疗反应的关系，能否在控制细胞组成和临床混杂后，在独立队列中保持”，在单细胞发现队列中提出候选，在独立 bulk 或其他单细胞队列验证。若有匹配的公开扰动数据或实验合作，再检验候选机制的支持证据。相关性、扰动证据和机制确认分别报告，不预设阳性发现。

启动前形成一页课题卡：具体疾病/条件、数据 accession 和版本、发现与验证集、主要统计对比、必要混杂因素、候选筛选规则、反证条件及责任人。当前尚无这些已选定材料，不能把“治疗反应”模板写成已经开展的课题。验证集在方法与候选规则冻结后才解封；冻结后新采集的数据可作前瞻分支，历史独立队列则准确称为外部验证。

需要增加的能力包括：供体和临床元数据检查、供体感知的差异分析、批次与混杂因素处理、预先划定发现/验证队列、效应量和不确定性输出。供体应作为适当的独立统计单位，不能把同一人的大量细胞当成大量独立受试者。

如果验证支持稳定的生物学关联，这一案例能连接两条论文路线。若要进一步主张调控机制或治疗靶点价值，还需要与主张相匹配的干预或功能验证；仅有细胞通讯推断、富集和文献解释不够。

### 泛化场景 未用于规则开发的 RNA 与 ATAC 长流程

在样本关系明确的数据中开展表达、染色质可及性和候选调控关联分析，检验跨步骤样本身份、参考版本、数据类型与长作业恢复。优先选择有专家参考分析的任务。

它适合作为保留的泛化证据，不在看过结果后为某个任务定制规则。峰到基因的关联不能自动解释为因果调控。没有配对样本或独立验证时，应缩小科学主张。资源有限时，先完成前两层，不为凑齐模态扩大范围。

### 有合作条件后再扩展 蛋白设计

现有 ProteinMPNN 探索可保留。若要成为主论文的应用，应补齐完整工具封装、固定模型资产、结构预测复核、同预算对照及适当功能实验。RFdiffusion 接入或增加一个结构查看器，只能扩展使用范围，不能证明设计成功。

现有 [Baker Lab 执行依据](bakerlab-execution-readiness.md) 和 [来源审计](bakerlab-source-audit.json) 已将跨工具流程、结构验证、同预算科学评测和湿实验列为未完成；不宜用该案例挤占首轮组学评测资源。

## 功能建设优先级

下表是论文研究的投入顺序，不替代项目路线图的 P0/P1/P2 定义。T1–T4 等正确性修复是可信实验的前提；拟新增的方法贡献需由跨步骤一致性机制及其独立实验证明。

| 顺序 | 建议功能                     | 可验收的结果                                                                       | 论文收益与范围                                         |
| ---- | ---------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 1    | 统一完成判定，先做 T1        | 所有相关路径对相同缺失主输出给出相同失败结论；无法解析的必需输出不可静默跳过       | 消除错误成功报告；小范围正确性修复                     |
| 2    | 运行时快照，推进 T2–T4       | 升级后旧运行仍导出旧 manifest；Notebook 保存实际环境和锁摘要；版本缺失明确标为未知 | 为独立重跑提供材料；复用已有 envId/版本记录            |
| 3    | 生产 Phi 科学任务评测入口    | 同一任务可无交互批量启动、重复、超时、收集证据和独立评分                           | 直接产生论文结果；复用 kernel、现有 eval 和 usage 记录 |
| 4    | 修订 T5 为样本完整性         | 检测重复 sample/mate、多 lane 冲突、明确 PE 的缺配对、清单与输入不一致             | 减少错误数据进入流程；保持现有 invalid 阻断            |
| 5    | T6–T8 的最小科学验收         | 一个 RNA-seq 场景有文件格式、必要字段、有效记录、领域 QC 与步骤后置检查            | 形成单步骤检查基线；先限定少量检查而非通用验证平台     |
| 6    | 跨步骤科学一致性原型         | 输入输出携带样本、参考、数据语义；合法衔接通过，已知不兼容衔接阻断，缺证据返回未知 | 新增研究增量；与单工具验证比较，单独制定规格和测试     |
| 7    | 扩展现有运行与产物的来源记录 | 样本、参考版本、参数、输入摘要、输出、QC 与报告中的关键结论可以相互追踪            | 支撑复核与 Methods 写作；不新建泛化知识图谱            |
| 8    | 独立队列及稳健性分析模板     | 同一假设能在保留队列重跑，并输出负结果、效应量、区间及敏感性分析                   | 支撑贯穿案例和应用论文；通过现有技能/流程实现          |

领域阈值需按数据类型和方法确定，不能把一个通用阈值硬套所有任务。输入校验只能发现可观察的不一致；若样本标签本身缺乏外部核对依据，系统不能凭文件名保证没有标签交换。

论文写作辅助可作为第7项的轻量输出：从真实运行记录生成 Methods 草稿、软件版本表和图表来源清单，给出每条关键结论对应的产物位置。先保证来源完整，再考虑正文自动写作。

当前降低优先级：手机端、社交/群聊、新模型训练、无明确任务需求的插件扩张、为了外观新增独立面板。它们可能改善产品，但尚未对应本论文的主要可测贡献；内测路线图也将多项此类能力放在后续版本。

## 平台论文的实验设计

### 从小规模预实验开始

先预先挑选6个有参考结果的任务，两种配置各做3次独立模型运行，共36次，用于工程可行性与成本估计。配置固定为完整Phi和“同工具、同模型、只移除跨步骤检查”的匹配对照，具体见开发任务R19。另建匹配的正常/异常输入对来验证评分器和误阻断；这些故障运行单列预算，不隐含在36次中。这个规模不作为正式论文充分统计功效的承诺。

预实验后固定主终点、数据划分、任务纳入标准、超时和资源预算，再决定正式任务数及重复数。正式研究尽量覆盖至少两个模型家族，并保留未用于调试的数据及步骤组合；具体规模由预实验方差与资源决定。正常有效输入上的科学评分作为主终点，边界错误检出作为预设机制终点，防止只靠拒绝任务提高表面可靠性。

### 对照与消融

| 组别                       | 条件                                                                             | 回答的问题                                           |
| -------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 通用智能体                 | 相同底座模型、软件可用性、数据、计算资源与时间预算                               | Phi 整体增加了多少收益                               |
| 经验证工具基线（核心消融） | 与 Phi 相同的模型、工具、计划和资料，保留文件/格式/QC 验证，仅关闭新增跨步骤检查 | 相对已有工具验证，新增机制有无独立价值               |
| 完整 Phi                   | 固定版本的生产执行路径与全部拟评测机制                                           | 主实验条件                                           |
| 最近邻公开系统             | Paper2Agent 或 CellVoyager 的共同支持任务；明确数据粒度、工具和模型匹配情况      | 与相关已发表系统的实际差异；不能执行的任务不任意记零 |
| Phi 去掉固定 Wrapper       | 其余机制尽量保持一致，允许同类工具自由编码调用                                   | 固定流程的贡献及灵活性代价                           |
| Phi 去掉结果验收           | 保留执行工具、计划和预算；移除新增验收关卡                                       | 是否确实减少错误成功报告                             |
| Phi 去掉恢复机制           | 只用于预设断网/重启等故障条件                                                    | 恢复机制减少了多少损失与重复工作                     |
| 专家固定流程参考           | 经复核的确定方法与产物                                                           | 提供准确性参考；与交互式智能体分开解释               |

若移除某机制会改变其他工具、提示或资源，明确记录这种差异，不把结果归因给单一因素。每组都从干净状态开始，避免缓存、历史记忆和调试产物泄漏；冷启动与预装环境的成本分开报告。所有子智能体、决策模型和自动重试的调用都计入总预算。

各组随机交错运行，记录具体模型版本、调用日期与计算环境，避免模型服务更新、时段和队列负载与实验组别重合。只能使用动态模型别名时，明确这一版本固定的限制。

最近邻系统对照不能替代严格消融。先划定共同可执行的任务交集并冻结版本；若模型、工具或数据访问无法匹配，就单列系统级比较，不将差异全归因于框架。只实现“经验证工具”基线时，应使用这个名称，不能标成已运行 Paper2Agent。对已有论文里的裸模型比较也保持同样标准。

在可比任务上，也将同样的检查规则用于非智能体的专家固定流程，区分一般质量检查的收益与动态组装流程中的收益。若简单确定性检查已经解释全部效果，就按这一结果界定贡献，不将其描述为新增的智能体推理能力。

故障集合分三层：文件缺失/截断等工程故障；样本、参考、矩阵语义等跨步骤故障；统计模型或生物学解释等推断错误。第一层检验基础质量，第二层检验本研究机制，第三层用于报告能力边界。加入预实验中自然发生的失败，公开规则覆盖率和无法识别的错误；禁止只保留新增检查能够轻易识别的案例。

### 指标与评分

| 指标           | 定义或报告方式                                                                         |
| -------------- | -------------------------------------------------------------------------------------- |
| 主科学终点     | 预先指定产物的独立科学评分；按任务先聚合，再汇总，避免产物多的任务主导结果             |
| 正常任务成功率 | 在有效输入任务中满足全部预设成功条件的比例                                             |
| 错误成功报告率 | 系统宣称成功但独立评分不合格的次数 / 系统宣称成功的次数，同时报告分子分母              |
| 故障处理       | 故障检出率、正常输入误报率、正确停止/求助率、发现问题后仍继续的比例                    |
| 一致性与复现   | 重复自主运行的结果一致性，以及第二环境按记录重建后与参考结果的容差一致性，分开报告     |
| 成本与效率     | 模型费用、CPU/GPU时、墙钟时间、队列等待、存储及人工干预次数；无法获得的 token 不填零   |
| 恢复质量       | 重复提交/计算次数、下游误启动、恢复所需人工操作和损失的计算时间                        |
| 研究解释质量   | 独立专家按预先定义量表判断证据支持程度、过度解释和遗漏的替代解释；与数值准确率分开报告 |

检查输出格式与必要列之后，再比较数值或领域指标：例如计数一致性、效应方向、预定基因集合的精确率/召回率。容差与生物学等价标准由参考分析和领域专家在查看组间结果前确定，不能只用文件名或关键词命中判正确。

输入与答案需要隔离：运行时验收器可以知道输出合同和领域 QC 规则，不能读评测方的隐藏参考答案。评分器由独立脚本执行，主分析不依赖同一个模型自评。人工判断部分采用明确量表并尽可能盲评。

统计时保留任务内配对；共享原始数据或队列的任务按研究/数据集聚类，彼此独立的任务才直接按任务聚类。产物、细胞、相关子任务或同任务重复尝试不能充当独立研究重复。采用相应聚类的 bootstrap 或合适的分层模型，报告效应差与置信区间；聚类身份在任务合同中预先固定。多重终点和子组分析预先约定，超时和失败不事后删除。

每次人为修改分组、参数、候选列表或分析解释都记录原因与耗时。单独披露人工数据准备、流程开发及实验执行，不以对话字数估计“自主率”。专家评价按科学问题、证据和替代解释评分，不能把叙述流畅程度当发现质量；模型自报的 confidence 也不能替代经验校准。

### 外部基准如何使用

BioAgent Bench 覆盖常见生信任务及损坏输入、诱饵文件等扰动，适合先验证稳健性；其原有评分包含 LLM judge。Phi 若增加独立文件/数值评分，应同时保留原协议分数并单列新增评分，不能混成同一个榜单结果。[BioAgent Bench](https://arxiv.org/html/2601.21800v2)。

BixBench3 提供研究规模的长流程任务和确定性产物评分，适合作为较大规模主实验的候选。先试运行少量任务检查工具、参数与资源兼容性；使用完整协议时保留网络和答案隔离规则。若改资源、删任务或换评分，只能报告明确注明的子集/改编实验。[BixBench3 论文](https://arxiv.org/html/2608.25286v2)、[公开运行与评分代码](https://github.com/EdisonScientific/BixBench3)。

外部基准用于检验已知分析的执行能力；真实研究案例用于检验工作台在实际问题中的价值。两者都不能单独证明“自主科学发现”。

上述基准是评测来源，不是本次 Nature 行文样板。CellBench 主要衡量分析选择时，也不能把其分数直接与原始数据到产物的执行评分合并。

## 论文写作提纲与图表

方法路线的工作题目调整为：**Phi: context-aware execution and verification of scientific workflows**。其中 context 指可检查的科学分析上下文，不是扩大语言模型上下文窗口。跨步骤机制尚待实现和验证，工作题目不代表现有版本已具备它；正式标题在主要结果确定后再定。

### 摘要和引言围绕一个缺口组织

摘要按“重要问题 → 现有方法的具体缺口 → Phi 的机制 → 最关键的定量证据 → 适用范围”组织成一段。现在只写前3项的研究动机；效应大小、任务数量和结果句由冻结实验填入，不能先写成功结论再挑数据。不要用功能清单代替主要发现。

Introduction 的第1段说明为什么跨工具、多数据来源的分析容易产生难以察觉的不一致，并用一个简短的研究情境解释后果。第2段承认已有工作解决了哪些问题：工作流与社区标准、经过验证的工具调用、Notebook 探索；相关工作融入论证，不另堆一段产品清单。第3段提出尚需检验的问题：单工具通过测试，是否足以保证跨步骤分析仍满足原设计。第4段概述研究机制、比较和独立验证的范围，结果出来后再给实际贡献。

### Discussion 和 Methods 各自承担的职责

Discussion 先解释主结果对科学分析实践意味着什么，再与最接近的方法比较；随后讨论固定约束与探索灵活性之间的代价、元数据错误和未知状态、规则覆盖不足、人工投入及模型漂移。最后限定推广范围。不要用未来插件列表替代局限讨论，也不要把外部关联验证写成因果证明。

Methods 应足以让另一团队重做研究，按主题说明：任务及队列纳排、数据划分和真值构建、软件与模型快照、Wrapper 选择和上下文约束、对照配置、扰动生成、评分容差与盲评、统计单位及缺失/失败处理、人工介入、计算与费用口径。每个分析产物对应可访问的数据来源和执行记录，另列 Data availability 与 Code availability。

扩展数据承接逐任务结果、各模型与提示版本、失败轨迹、规则覆盖、正常输入误报、完整消融、环境与调度日志、参数敏感性；补充材料提供完整提示、工具声明、任务清单和重跑说明。主图中的每个统计量配底层 source data 与生成脚本。GUI、安装和插件目录移到软件文档或补充演示。

按当前 Nature Methods Article 指南，规划不超过150词的无引文摘要、约3,000词正文和不超过6个主图表，使用无标题引言、Results、Discussion 和 Online Methods；这只是该文章类型的写作预算，不能套到整个 Nature 系列。Brief Communication 有不同结构，不能把本文机械删短。[当前文章类型说明](https://www.nature.com/nmeth/content)。

若后续转向发现型论文，应按“科学问题 → 候选与证据 → 新数据/实验 → 假设修订 → 独立验证”重新组织，Phi 架构以解释研究过程所需为限。已有外部队列重分析和真正新增实验分开标记；真实科研中的人类决定完整披露。没有新发现时保留方法路线，不代写含发现结论的摘要。

推荐先完成 A、B 再决定是否扩大应用。若预实验主要失败来自工具覆盖，就补对应工具；若来自样本身份或判定错误，就补验证；若来自模型科学推理，不能指望增加界面或持久化功能解决。若相对经验证工具基线没有明确增益，转为适当的软件/资源或评测贡献；若新发现可独立成立，再增加发现型论文投入。这些是内部研究决策条件，不是期刊录用阈值。
